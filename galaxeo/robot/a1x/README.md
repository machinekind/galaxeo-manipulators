# Galaxea A1X for the digital twin

The A1X as a robot folder for the digital twin (`machinekind_twin`): `robot.yaml`, the MuJoCo model
`a1x.xml` it names, and `demo.json`, the example workspace `twin demo --robot a1x` copies.
The twin finds this folder through the `machinekind_twin.robots` entry point of the galaxeo package.

## Source

* The model comes from the vendor URDF `ros2_ws/src/galaxea_a1xy_description/urdf/a1x.urdf` and
  the meshes in `galaxeo/arm/assets/meshes/` (byte-identical to the description package's). The
  model's `meshdir` points there; nothing is copied. So this folder is not self-contained:
  copying it alone (e.g. to a GPU box) loses the meshes; install galaxeo there instead.
* Licence: vendor URDF and meshes (Galaxea), `Proprietary` in the description package's
  `package.xml`. **Not Apache-2.0.** The vendor's licence terms are not written down anywhere.
* `a1x.xml` is generated by `import_twin_model.py` at the repository root, on the path of
  `sim/urdf2mjcf.py`: masses, inertias, joint axes and ranges from the URDF, position servos,
  box colliders for the jaws, the jaws coupled by an equality, keyframe `home`. Do not edit it by
  hand.

## Post-processing rules

What the twin's model has that `sim/urdf2mjcf.py` does not make:

1. Joint `gripper_finger_joint1` is named `gripper` (joint, actuator, equality). The second jaw
   stays `gripper_finger_joint2`, coupled as `q2 = -q1`. Keyframe `home` unchanged.
2. Actuators are named after their joints (`arm_joint1..6`, `gripper`).
3. The collision boxes of the curled jaw tips are named `finger1_tip` / `finger2_tip`.
4. `<option integrator="implicitfast" timestep="0.002" cone="elliptic" impratio="10"/>`: the step
   of `sim/scene.xml`, cone and impratio as the SO-101 in MuJoCo Menagerie. No
   `noslip_iterations`: the twin's scene does not copy it and MuJoCo Warp does not support it.
5. Site `tcp` as generated: `x` = approach, `y` = jaw closing axis.
6. The jaw equality is stiffer than the default: `solref="0.01 1"`,
   `solimp="0.99 0.999 0.001 0.5 2"`. The real gripper is one stiff degree of freedom. With the
   default equality the jaws drifted apart in RL (5 ms step, violent arm actions, table contact)
   by up to 36 mm; now about 12 mm at worst, usually 2-5 mm. A time constant below 0.01 s changes
   nothing at a 5 ms step (MuJoCo raises it to 2 x step).

`tests/test_robot_a1x_model.py` checks each rule, and that the script reproduces the committed
`a1x.xml` byte for byte.

## Regenerate

    python import_twin_model.py                         # from ros2_ws/.../urdf/a1x.urdf
    python import_twin_model.py --urdf <newer a1x.urdf>  # from a newer vendor URDF

A newer URDF with new meshes needs them in `galaxeo/arm/assets/meshes/` too.

## Checked in the twin's simulation

Measured in the twin with this model:

| Check | Result |
|---|---|
| camera calibration, `twin calib-sim --robot a1x --n 3 --cameras 2` | 6/6 trusted. Median 0.24 mm / 0.017°, worst 0.82 mm / 0.041°, residual 0.21 px |
| calibration session, seed 0, 1 camera | 16 poses, 0.20 mm, 0.017° |
| camera from the side (about 180° to the base), seed 1, 2 cameras | 2/2 trusted. It was 0/2 before the twin's rotation-median fix in `calib/handeye.py` |
| IK to reach goals at A1X scale | 20/20, worst 0.33 mm |
| calibration wave: poses with the card over the table | 85 % (170/200) |
| physics at a 5 ms step, random actions near the cube (2400 ticks) | no NaN. The cube moves at most 2.0 m/s and rises at most 23 mm above the table |
